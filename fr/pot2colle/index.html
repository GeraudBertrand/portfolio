Pot2Colle

L'audit d'un site existant pour un enseignant, puis les corrections : structure, performances, sécurité. Un projet de séminaire dans une grande équipe mêlée.

Lire les recommandationsLire l'étude de la concurrence

La demande

Un enseignant voulait que son site marche mieux. Il fallait trouver ce qui n'allait pas, l'expliquer à quelqu'un qui n'est pas développeur, recommander des changements, et les faire.

Ce que nous avons changé

  • Du code dupliqué réorganisé en architecture Modèle-Vue-Contrôleur.
  • Un nouveau schéma MySQL pour les comptes utilisateurs.
  • Chargement différé, et images passées en SVG et WebP.
  • Une authentification par rôles : enseignant, parent, élève.

Ce que j'en retiens

  • Expliquer la dette technique et le MVC à un client qui n'a pas besoin des mots, seulement des conséquences.
  • Des données d'enfants sur un site scolaire : le RGPD n'est pas une note de bas de page.
  • Coordonner le code avec Git à treize, dont la plupart n'étaient pas développeurs.
