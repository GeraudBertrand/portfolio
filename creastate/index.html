Transmutation · the workshop, Créalab

CreaState

The platform of Créalab, the maker space of my school: print and cutting requests, 3D-printer monitoring, inventory, maintenance, members. I built the first version alone; it is now being tested.

Why

A maker space receives all kinds of requests: a part to print, a sheet to cut, a machine to repair, a training session to plan. CreaState tries to answer each of them in one place, instead of one tool per need. It is less a single site than a set of tools for the association.

What it does

  • A public side for students: submit a print or cutting request, follow it, talk about it in a chat.
  • A private side for members: dashboard, printers, requests, inventory, maintenance, events, training sessions.
  • Live state of the Bambu Lab printers, read over MQTT.
  • Sign-up restricted to the school's e-mail domain, with permissions per role.

Where it stands

I designed it, built it and produced the first version. The association is now testing it, to decide whether it will be adopted in full. Whatever the answer, it maps what Créalab actually needs, and that alone was worth doing.

How it is built

Blazor Server on .NET 9 with REST controllers in the same host, MySQL through Entity Framework, ASP.NET Core Identity. Permissions in the database become claims, then policies; a role is just a set of permissions. Packaged with Docker, meant to run on a Raspberry Pi in the workshop.

What it taught me

  • In Blazor Server there is no HTTP context inside the live connection, so login has to go through a form posted to a controller.
  • Talking to real machines: MQTT over TLS, reconnections, shared state in memory.
  • The same authorization pattern as DevisNet. Each project improves the other.
